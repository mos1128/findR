- 判据一条命令：`git log --oneline <手机包的构建提交>..HEAD -- apps/`

  其后只有 M4 的 **core 侧**代码（未接任何 UI）与文档改动。
- **签名已查实**：APK 用随 Expo/RN 模板分发的标准 debug 证书
  SHA-1 `5E:8F:16:06:2E:A3:CD:2C:4A:0D:54:78:76:BA:A6:F3:8C:AB:F6:25`，
  SHA-256 `FA:C6:17:45:...:3B:9C`。⇒ 模板不变则下次出包签名一致，**可覆盖安装、数据保留**。
  切正式 keystore 才必须卸载重装（清空本地记忆库）⇒ 先把导出 UI 做完。
- **验证方法（踩过的坑）**：`keytool -printcert -jarfile <apk>` **读不了** —— AGP 只做
  v2/v3，不做 v1 JAR 签名，会报「不是已签名的 jar 文件」。正确做法：
  `keytool -exportcert -alias androiddebugkey -keystore apps/mobile/android/app/debug.keystore
  -storepass android -file c.der`，再确认 `c.der` 的字节出现在 APK 的 Signing Block 内；
  或用 python 直接解析 APK Signing Block（EOCD → 中央目录偏移 → 尾部 24 字节取 size+magic
  `APK Sig Block 42` → 遍历 id 对，v2 = `0x7109871a`）。
- 本机工具：`keytool`/`java` 在 `D:\my-software\scoop\apps\openjdk21\current\bin`
  （不在 PATH，需全路径）；注意 keytool 是 Windows 程序，**不认 `/c/...` 形式的路径**，
  要传 `C:/...`。
- 顺带：`apps/mobile/android/`（含 `app/debug.keystore`）是 `expo prebuild` 产出的，
  未进版本库（`.gitignore`），所以本地跑 prebuild 也能拿到同一个 debug 证书。

## M4 3a 的前置调研：RN 侧 crypto 结论（别再重复调研）

翻了一遍 **expo-crypto 57.0.3** 的实际代码（`node_modules/.pnpm/expo-crypto@57.0.3_...`）：

- **自带原生 AES-GCM**：`expo-crypto/build/aes` → `AESEncryptionKey.import(bytes)` /
  `aesEncryptAsync` / `aesDecryptAsync` / `AESSealedData.fromParts(iv, ct, tag)`。
  原生模块名 `ExpoCryptoAES`，Android 实现是 `javax.crypto` 的 `AES/GCM/NoPadding`
  （`android/src/main/java/expo/modules/crypto/aes/`）。
  ⇒ **不需要新增任何原生依赖**，它已经随现有 expo-crypto 编进 APK 了。
  （原先「crypto 没装实现库、要么 quick-crypto 要么 WebCrypto」的判断作废）
- ✅ **16B nonce 的疑虑解除**（原列为「必须实测」）：`EncryptOptions.gcmParameterSpec()`
  直接把调用方传入的 IV 放进 `GCMParameterSpec(tagBits, iv)`，**无长度校验**（默认 12 只是默认值）；
  解密侧从 sealed data 读回同一 IV。Conscrypt 支持非 12 字节 IV ⇒ 设计文档的 16B 布局可行。
- ⚠️ **缺口：没有 KDF**。expo-crypto 只有 digest / random / AES，无 PBKDF2。
  `digestStringAsync` 循环 60 万次 = 60 万次 bridge 调用，不可行。
  计划：`@noble/hashes` 的 pbkdf2（纯 JS、Hermes 可用）放
  `apps/mobile/src/platform/crypto.ts`；**必须分片 + await 让出主线程**，
  否则 600k 迭代会把界面冻住。实测太慢再换 `react-native-quick-crypto`（只动这一个文件）。
- 相关事实：`apps/mobile/src/capture/submit.ts` 已经在用 `expo-crypto` 的 `randomUUID`
  （所以自检屏那行「crypto.randomUUID 不可用（已走兜底）」不是 bug）。
