## 踩到的坑（已解，值得记）
1. **`_nullishEnumOf` 的泛型推断污染**：`schema.dart` 里 helper 返回 `T?` 会让调用处 `T` 被推成 `T?`，
   与 `String Function(T)` 不匹配 ⇒ 显式写 `_enumOf<T>(...)`。
2. **`is! ParseOk` 不做类型提升**：sealed `ParseResult<T>` 在多次赋值后 promote 会失效 ⇒
   改用 `switch (parsed) { case ParseOk(:final value): ... case ParseFailure(:final error): ... }` 穷尽匹配。
3. **`unnecessary_cast`**：Dart 的 `r as Foo` 会**提升 r 本身**，所以同一个变量连写两次 cast，第二次是多余的
   ⇒ 先 `final v = (r as Foo).value;` 再用 `v`。
4. 一条**测试断言**（不是我实现错）：`fixJson('[1, 2, ]')` 的结果是 `'[1, 2]'` 而不是 `'[1, 2 ]'` ——
   `,\s*` 把逗号和空白一起吃掉了，TS 行为完全相同。

### 踩到的坑（已解，值得记）
1. **`prefer_initializing_formals` 会误报在「具名参数 → 私有字段」上**（Dart 的具名参数不能下划线开头）。
   解法：`int? timeoutMs` + 初始化列表里 `?? 默认值`（顺带与 TS 的 `opts.x ?? 默认值` 语义**更**一致）；

### 1. `image` 包埋的两个雷（都是实测才发现，都已写进代码注释 + 测试）
**雷一：`encodeWebP` 默认 `lossless: true`，而无损模式下 `quality` 被完全忽略。**
只写 `encodeWebP(x, quality: 80)` 会得到一个「参数看着对、体积大一倍以上、且毫无报错」
的**无损** WebP。包自己的注释写着「`encodeWebP(image, quality: 40)` on its own does nothing
at all: pass `lossless: false` first」。→ 必须 `lossless: false` 才谈得上 quality。

**雷二：EXIF 方向**已经由 JPEG 解码器烤进像素了，**别自己再补一次**。
`decodeImage(jpeg)` 出来的对象 `exif` 是空的，看着像漏读了方向 —— 我一度真去补了一刀
（`decodeJpgExif` 读回方向 → 赋给 `decoded.exif` → `bakeOrientation`），**结果转了两遍**：

真相在 `_jpeg_quantize_io.dart`：解码时就读了方向、转了像素、**把 orientation 清成 null**

**utf-16-le** 找包名 / label；③ 在整个 APK 字节里找 `APK Sig Block 42` 与
`struct.pack('<I', 0x7109871a)` 判 v2 签名、找 `Android Debug` 判 debug 证书。
**META-INF 里没有 `.RSA` 是正常的** —— minSdk 24 起 AGP 默认不签 v1（签名在 APK Signing Block 里），
别当成「没签名」。
