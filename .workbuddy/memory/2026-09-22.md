## 踩到的坑（已解，值得记）
1. **`_nullishEnumOf` 的泛型推断污染**：`schema.dart` 里 helper 返回 `T?` 会让调用处 `T` 被推成 `T?`，
   与 `String Function(T)` 不匹配 ⇒ 显式写 `_enumOf<T>(...)`。
2. **`is! ParseOk` 不做类型提升**：sealed `ParseResult<T>` 在多次赋值后 promote 会失效 ⇒
   改用 `switch (parsed) { case ParseOk(:final value): ... case ParseFailure(:final error): ... }` 穷尽匹配。
3. **`unnecessary_cast`**：Dart 的 `r as Foo` 会**提升 r 本身**，所以同一个变量连写两次 cast，第二次是多余的
   ⇒ 先 `final v = (r as Foo).value;` 再用 `v`。
4. 一条**测试断言**（不是我实现错）：`fixJson('[1, 2, ]')` 的结果是 `'[1, 2]'` 而不是 `'[1, 2 ]'` ——
   `,\s*` 把逗号和空白一起吃掉了，TS 行为完全相同。

### 踩到的坑（已解，值得记）
1. **`prefer_initializing_formals` 会误报在「具名参数 → 私有字段」上**（Dart 的具名参数不能下划线开头）。
   解法：`int? timeoutMs` + 初始化列表里 `?? 默认值`（顺带与 TS 的 `opts.x ?? 默认值` 语义**更**一致）；

### 4. 自检屏改成两组
核心组（FTS5 命门）**优先跑在真实库文件上** —— 那才是真机上真正会用的库，

并在标题里**写明跑在哪**。设备组跑那 5 项或显式说明「未运行（不算失败）」。
