## 真机验收第 ① 条撞出 release-only 大坑：release 包没带 INTERNET 权限

### 症状（用户报，附截图）
- 探测两行全红：`ClientException with SocketException: Failed host lookup:
  'api.deepseek.com' (OS Error: No address associated with hostname, errno = 7)`
- **配置与旧版 RN 完全一样，旧版能通** ⇒ 排除手机网络/DNS，是 App 的问题。

### 根因（三层叠在一起，所以之前从没暴露）
1. `main/AndroidManifest.xml`（release 用的）**没声明 `INTERNET`** —— 迁移重写清单时
   「权限全交给插件合并」的判断只对了一半。
2. Flutter 模板在 `debug/`、`profile/` 清单里**自带** INTERNET ⇒ `flutter run` 一切正常。
3. **没有任何插件会替你带 INTERNET**（connectivity_plus 只带 ACCESS_NETWORK_STATE、
   record 只带 RECORD_AUDIO）。

### 证据链
- 源码：`apps/flutter/android/app/src/{main,debug,profile}/AndroidManifest.xml` 三份对比。
- **对着发出去的 APK 验**（Python 读二进制清单，字符串池 UTF-16LE）：
  `ACCESS_NETWORK_STATE` ✅、`RECORD_AUDIO` ✅、`INTERNET` ❌ —— 插件带的都在、没人带的缺失。
- 排查姿势：报错是 `errno = 7`（域名解析）而不是「无网络」，但同一台手机旧版通 ⇒ 必是包内差异。

### 修
- `main` 清单补 `<uses-permission android:name="android.permission.INTERNET"/>`，
  注释写明为什么不能靠插件。
- **CI `apk` 作业加产物级闸**：读构建出的 APK 清单，UTF-8 / UTF-16LE 双编码断言
  `android.permission.INTERNET` 在。理由同 fts5 那道闸。
- 验收：`flutter analyze` 无问题 · `flutter test` 83 通过；出包 run 35814094194。

### 教训（值得单独记）
- **「权限不用自己写」这条口诀对 debug 成立、对 release 不成立。**
- 通用化：凡是从 RN 迁移来的能力，逐个问「RN 那边权限是谁带的、Flutter 这边谁带」。
- 这次再次验证「先验完、再重构」的顺序：**验收第 ① 条、第一分钟就抓到一个
  自动测试和自检屏都抓不到的 bug** —— 它只在 release + 真机上存在。

## 备份带上 API Key（用户要求，**属需求变更**）

⚠️ **与需求.md:48「导出备份不含 Key」直接冲突** ⇒ 这是用户拍板改需求，已同步三份文档。
代价讲在明处：**包是明文，带 Key = 把密钥明文交给拿到文件的人**（导出完一步就是分享面板）。

设计（两条通道分开，各管各的开关）：
- `settings` 白名单**没动**（Key 从不走这条）；
- Key 走 manifest 的**可选字段** `apiKeys`，由平台层显式传入，**core 只搬不读**
  （core 不该依赖 `flutter_secure_storage`）⇒ 「默认不带」，界面上的勾选才有意义；
- 导入侧 **只填本机为空的槽位**（不覆盖已有 —— 与「导入不删本地数据」同口径）。
  这条抽成了纯函数 `planKeyRestore`（`platform/secure.dart`）⇒ 能被单测押住。

界面：导出面板加「带上 API Key」开关（**默认开**），确认框**点名 Key**
（不能只说「内容是明文」—— 多数人听到「内容」只想到自己的卡片）。

测试 +12：core 备份 5 条（不传不带 / 传了能取回 / 明文可搜到 Key 是已知代价 /
老包无该键 / 空 map 语义）+ app 7 条（`planKeyRestore` 六种情形 + 掩码）。
